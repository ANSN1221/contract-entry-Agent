# 演示脚本（3 分钟版）

给面试/汇报用的分镜。全程只在一个页面里操作，不切终端（终端只在开场露一次）。

## 0. 开场（20 秒）

```bash
uv run python scripts/demo.py --fresh
```

指着输出说：

> 一条命令做四件事：环境自检、库迁移、签发 12 小时 token、起服务。
> 自检会明确告诉我哪个依赖缺失、该跑什么命令补——不是启动失败让你猜。

把 token 粘到页面右上角。

## 1. 痛点与方案（30 秒）

> 合同录入的痛点是「双人复核」：一个人念、一个人敲，慢且易错。
> 做法不是让模型直接写库，而是让模型**只能引用条款原文**：
> 每个字段必须带条款 ID 和原文片段，没有出处就给空、标红、等人确认。
> 一句话：AI 抽取，人负责签字。

## 2. 建任务 → 抽取（40 秒）

点「创建示例任务」→「开始抽取」，观察右侧：

- 时间线滚出四条事件（开始执行 / 字段抽取完成 / 证据校验完成 / 等待人工确认）
- 12 个字段填满，证据列显示条款 ID + 命中的原文

讲这里的两句话：

> 时间线是 SSE 推的，不是轮询。
> 每个字段的置信度和出处都在面上，不需要点开二级页面。

## 3. 证据链（40 秒）

指 `生效日期` 那一行（标黄、置信度 0.00、无出处）：

> 这份合同确实没写生效日期。模型没有拿「履行期限起点」去猜——
> 提示词里明确写了：找不到就填 null，编一个比空着更糟。
> 这一条是整个系统的价值主张，不是缺陷。

再指 `履约保证金比例`：

> 原文写「百分之五」，抽出来是 5。规则层查不到，自动降级到模型复核，
> 复核结论写在证据列。判不了就是「未验证」，不会默认通过。

## 4. 人工确认 → 写库（30 秒）

把生效日期改成 `2026-04-01`，点「确认并写库」：

> 确认后 token 立即作废，二次提交一定 409。
> 审计链记到「人」：谁在什么时候改了哪个字段。

## 5. 可靠性（20 秒）

打开 `http://127.0.0.1:8000/docs`，说：

> 状态机是白名单，非法迁移 409；任务带版本号做乐观锁；
> 执行有 120 秒超时和 3 次上限，超了进死信不再占用 worker。

## 6. 收尾（20 秒）

```bash
curl -s http://127.0.0.1:8000/metrics | head -12
```

> 指标从库里聚合，不是内存计数器——重启不归零，多 worker 也对得上账。
> 评测脚本跑同一份合同：字段 12/12、引用可核对 100%、不可答 8/8、2165 token、7.7 秒。

## 备用问答

| 问 | 答 |
| --- | --- |
| 为什么不用现成的合同抽取 SaaS | 数据出不去；且要求的不是「抽得准」，是「每条都能核对」 |
| 模型抽错了怎么办 | 三层兜底：置信度阈值、证据校验、人工确认卡；校验结论为 unverified 的一律过人眼 |
| 换个合同还能用吗 | 检索与抽取都和合同类型解耦，12 字段是通用字段；换领域只需要改字段表和提示词 |
| 现在最大的短板 | 评测集只有 1 份合成合同，真实语料（15 份公开采购合同）还没下载；结论的统计意义有限 |
