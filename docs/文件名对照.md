# 文件名对照

## 一、根目录

| 文件 / 目录 | 英文原意 | 中文 | 干什么的 |
| --- | --- | --- | --- |
| `app/` | application | 应用 | 所有业务代码都在这一层 |
| `tests/` | tests | 测试 | 自动化验收单 |
| `docs/` | documents | 文档 | 说明性文件，不参与运行 |
| `README.md` | read me | 读我 | 项目说明书，GitHub 首页展示的就是它 |
| `LICENSE` | license | 许可证 | 法律授权条款（建仓时生成的 MIT） |
| `pyproject.toml` | project configuration | 项目配置 | 依赖、Python 版本、工具配置。`toml` 是配置格式名 |
| `alembic.ini` | — | 迁移工具配置 | Alembic 的配置文件；连接串由 `migrations/env.py` 从项目配置注入，不在这里写死 |
| `migrations/` | migrations | 迁移 | 数据库结构变更脚本，`versions/` 下按时间累积 |
| `uv.lock` | lock | 锁文件 | 依赖的**精确版本快照**，别人 `uv sync` 能装出一模一样的环境。不要手改 |
| `.env.example` | environment | 环境变量样例 | 配置模板，复制成 `.env` 后填真实值；`.env` 含密钥，不进仓库 |
| `.gitignore` | ignore | 忽略清单 | 哪些文件不纳入版本管理（`.venv`、`.env`、数据库文件） |
| `.gitattributes` | attributes | 文件属性 | 统一换行符，避免 Windows 与 Mac 协作时出现假改动 |

## 六、命名约定（本项目遵守）

1. 文件名全小写，多个词用下划线：`state_machine.py`，不用 `StateMachine.py`
2. 测试文件必须 `test_` 开头，测试函数也必须 `test_` 开头
3. 一个文件一个主题：`errors.py` 只管错误，不塞业务逻辑
4. 目录名用复数表示集合：`tests/`、`adapters/`、`api/`
5. 配置文件用点开头隐藏：`.env`、`.gitignore`
